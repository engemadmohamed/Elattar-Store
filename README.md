# Al Attar | العطار — متجر القرطاسية والأدوات المكتبية

متجر إلكتروني كامل (Express + MongoDB + React) لبيع الأقلام والدفاتر والأدوات
المكتبية، مع لوحة تحكم للأدمن لإضافة المنتجات وتوليد QR Code لكل منتج.

## ⚠️ قبل أي حاجة: أمن قاعدة البيانات

رابط الـ MongoDB الأصلي اتبعت في محادثة نصية عادية، وده معناه إنه لازم
تتعامل معاه كأنه مكشوف بالفعل:

1. روح على MongoDB Atlas → Database Access
2. غيّر باسورد المستخدم `emadmohamedemadarefabdelhamid_db_user`
3. حدّث قيمة `MONGO_URI` في ملف `.env` بالباسورد الجديد

## الإعداد (Setup)

```bash
npm install
```

الملف `.env` موجود بالفعل في جذر المشروع ومعبأ ببياناتك (لا يُرفع على git).
راجع القيم دي فيه قبل أول تشغيل:

| المتغير                                    | الوصف                                                        |
| ------------------------------------------ | ------------------------------------------------------------ |
| `MONGO_URI`                                | رابط قاعدة البيانات (غيّره بعد تدوير الباسورد)               |
| `JWT_SECRET`                               | مفتاح تشفير الجلسات — تم توليده عشوائيًا بالفعل              |
| `ADMIN_SEED_EMAIL` / `ADMIN_SEED_PASSWORD` | بيانات أول حساب أدمن، غيّرها قبل التشغيل                     |
| `VITE_ADMIN_PATH`                          | رابط لوحة التحكم السري (بدل `/admin`) — غيّره لأي حاجة تحبها |

### لو قاعدة البيانات فيها بيانات قديمة (مثلاً من مشروع سابق)

الإعداد الحالي بيوجّه على قاعدة بيانات باسم `el-attar` منفصلة داخل نفس
الـ cluster، فمفيش تعارض مع أي بيانات قديمة تلقائيًا. لو عايز تمسح كل حاجة
من الـ cluster بالكامل بدل كده:

```bash
npm run db:reset   # يمسح كل الـ collections في القاعدة المتصلة
npm run seed        # يضيف حساب الأدمن + الفئات (أقلام، دفاتر، ...الخ)
```

### صور المنتجات (Cloudinary)

الموقع دلوقتي بيرفع صور المنتجات على [Cloudinary](https://cloudinary.com) بدل ما يحفظها كملفات محلية — يعني الصور هتفضل شغالة مهما نزّلت نسخ جديدة من المشروع أو غيّرت الجهاز.

**اعمل حساب مجاني (دقيقتين) واربطه بالمشروع:**

1. روح على [cloudinary.com](https://cloudinary.com) واعمل حساب مجاني (الخطة المجانية سخية جدًا وكافية لمتجر زي ده).
2. بعد تسجيل الدخول، من الأفضل تروح على الإعدادات (Settings ⚙️) ← **API Keys** وتعمل مفتاح جديد (`Generate New API Key`) وتسميه `El Attar` عشان يكون منظم. لو عايز تستخدم المفتاح الافتراضي، هتلاقيه في الـ **Dashboard**.
3. سواء استخدمت مفتاح جديد أو الافتراضي، هتحتاج 3 قيم:
   - `Cloud name`
   - `API Key`
   - `API Secret` (اضغط على "Show" لإظهارها)
4. انسخهم في ملف `.env`:
   ```
   CLOUDINARY_CLOUD_NAME=القيمة_بتاعتك
   CLOUDINARY_API_KEY=القيمة_بتاعتك
   CLOUDINARY_API_SECRET=القيمة_بتاعتك
   ```
5. **أعد تشغيل الخادم** (`npm run dev`). أي صورة ترفعها من صفحة إضافة منتج هترفع مباشرة على Cloudinary.

#### استكشاف الأخطاء: "فشل رفع الصورة"

إذا ظهرت لك رسالة خطأ تفيد بفشل رفع الصورة بعد إعداد Cloudinary، فالسبب غالبًا هو أن أحد بيانات الاعتماد (credentials) غير صحيح.

- **تأكد من نسخ القيم بدقة:** ارجع إلى لوحة تحكم Cloudinary وتأكد من أنك نسخت `Cloud name` و `API Key` و `API Secret` تمامًا كما هي، بدون أي مسافات إضافية في البداية أو النهاية.
- **تأكد من أسماء المتغيرات:** يجب أن تكون الأسماء في ملف `.env` هي `CLOUDINARY_CLOUD_NAME` و `CLOUDINARY_API_KEY` و `CLOUDINARY_API_SECRET`.
- **أعد تشغيل الخادم:** **مهم جدًا!** بعد أي تعديل على ملف `.env`، يجب إيقاف الخادم (عبر `Ctrl + C` في الـ terminal) وتشغيله مرة أخرى بالأمر `npm run dev` لتطبيق التغييرات.

لو سبت القيم الثلاثة فاضية، الموقع هيرجع تلقائيًا يحفظ الصور محليًا (نفس السلوك القديم، بنفس عيوبه — راجع `UPLOADS_DIR` تحت لو محتاجه كحل مؤقت).

### لو الصور مش بتظهر بعد ما نزّلت نسخة جديدة من المشروع (الوضع القديم بدون Cloudinary)

لو مكنتش لسه ربطت Cloudinary، الصور كانت بتتحفظ كملفات على القرص جوه فولدر `uploads/` **داخل فولدر المشروع نفسه**، لكن قاعدة البيانات ثابتة ومشتركة بين كل نسخة تنزّلها — فالصور القديمة بتفضل مربوطة بملفات مش موجودة في الفولدر الجديد.

**الحل الدائم لو مش عايز تستخدم Cloudinary:** في `.env`، حط `UPLOADS_DIR` على مسار ثابت برّه فولدر المشروع، مثلاً على ويندوز:

```
UPLOADS_DIR=C:\ElAttarUploads
```

### التشغيل

```bash
npm run dev
```

- الواجهة: http://localhost:5000
- الـ API: http://localhost:3001
- لوحة التحكم: `http://localhost:5000/<VITE_ADMIN_PATH>/login`
  (القيمة الافتراضية موجودة في `.env`)

## الميزات

- **متجر عام**: تصفح حسب الفئة/الفئة الفرعية، بحث، سلة، صفحة منتج، إتمام طلب
- **حساب عميل**: تسجيل/دخول للعملاء (`/signup`, `/login`) منفصل تمامًا عن الأدمن
- **لوحة تحكم أدمن** (على رابط سري): إدارة المنتجات، الفئات، الطلبات
- **QR Code لكل منتج**: يتولد تلقائيًا عند إضافة المنتج، قابل للطباعة/التحميل،
  ولما يتم مسحه بيفتح صفحة المنتج مباشرة للشراء
- **شحن**: اختيار شركة شحن (بوسطة/أرامكس/J&T/مايلرز) وحساب التكلفة والمحافظة
  عند إتمام الطلب

## الأمان

- كلمات مرور الأدمن والعملاء مشفّرة (bcrypt)، لا تُخزَّن نصًا صريحًا أبدًا
- الجلسات عبر JWT، بمفتاح سري في `.env` فقط
- لوحة التحكم على رابط غير متوقَّع بدل `/admin`، وبدون أي بيانات دخول افتراضية
  ظاهرة على الشاشة
